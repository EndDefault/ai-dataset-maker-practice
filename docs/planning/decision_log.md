# 의사결정 기록

이 문서는 프로젝트를 만들면서 중요한 방향을 왜 선택했는지 기록한다. 나중에 README, 자소서, 면접 답변을 만들 때 근거로 사용한다.

## 2026-06-01 AI 답변 생성에서 데이터 제작으로 방향 전환

결정:

- AI가 정답을 완성하는 챗봇보다, 사람이 검수 가능한 학습 데이터 후보를 만드는 도구에 집중한다.

이유:

- 작은 로컬 LLM은 비용 없이 실험하기 좋지만 말투 유지, 사실 정확도, 긴 답변 안정성이 약했다.
- 모델이 모르는 내용을 그럴듯하게 만드는 할루시네이션 문제가 있었다.
- 파인튜닝에 쓸 데이터는 사람이 통제한 사실과 검수된 답변이어야 품질을 유지할 수 있다.

영향:

- 데이터 제작 탭을 추가했다.
- 질문, 핵심 사실, 원하는 말투를 따로 입력하는 흐름을 만들었다.
- AI는 초안 생성 보조 역할로 두고, 최종 답변은 사람이 수정해서 저장하는 방향으로 바뀌었다.

## 2026-06-02 문서 체계 분리

결정:

- `docs`를 요구사항, 데이터 모델, 테스트, 로그, 포트폴리오 방향성 문서로 나누어 관리한다.

이유:

- 하나의 상태 문서에 모든 내용을 넣으면 프로젝트가 커질수록 찾기 어려워진다.
- 포트폴리오에서 설명할 문제 정의, 구조, 한계, 개선 방향을 따로 관리할 필요가 있다.
- 기능을 추가할 때 문서도 함께 갱신하는 습관을 만들기 위해서다.

영향:

- `requirements`, `data`, `checklist`, `test_plan`, `implementation_log` 등으로 문서를 분리했다.
- 커밋 메시지 규칙과 문서 갱신 규칙을 만들었다.

## 2026-06-02 코드 구조는 바로 옮기지 않고 폴더부터 만든다

결정:

- 기존 JavaScript 파일을 바로 이동하지 않고, 먼저 `src` 폴더 구조만 만든다.

이유:

- 지금 파일 이동까지 같이 하면 import 경로 변경으로 앱이 깨질 수 있다.
- 아직 기능이 계속 바뀌고 있으므로, 먼저 어디에 무엇을 둘지 책임을 정하는 편이 안전하다.
- 다음 기능부터 새 구조에 맞춰 점진적으로 분리하는 것이 추적하기 쉽다.

영향:

- `src/core`, `src/features`, `src/ui`, `src/api`, `src/utils` 폴더를 만들었다.
- 기존 `app.js`, `chat.js`, `dataset.js` 등은 아직 유지한다.
- 다음 리팩터링은 데이터셋 검수 기능을 만들면서 `dataset` 영역부터 분리한다.
