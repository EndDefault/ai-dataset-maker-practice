# AI Maker Studio 포트폴리오 방향성

이 문서는 이 프로젝트를 왜 만들고 있는지, 어떤 문제를 해결하려고 하는지, 포트폴리오에서 어떻게 설명할 수 있는지 정리한다.

## 프로젝트를 계속 만드는 이유

이 프로젝트는 단순히 챗봇을 만드는 것이 아니라, 목적별 LoRA를 만들기 위한 데이터 제작과 검수 흐름을 실험하는 프로젝트다.

파인튜닝 자체가 모든 문제를 해결해주지는 않는다. 파인튜닝으로 얻기 좋은 것은 새로운 지식 주입보다 말투, 형식, 반응 방식 같은 습관의 안정화에 가깝다. 그래서 이 프로젝트의 핵심은 모델에게 모든 정답을 맡기는 것이 아니라, 사람이 사실과 기준을 통제하고 AI는 초안 생성을 돕게 만드는 것이다.

## 해결하려는 문제

작은 로컬 LLM을 직접 써보면 다음 문제가 있다.

- 말투가 일관되게 유지되지 않는다.
- 사실을 모를 때도 그럴듯하게 답하는 할루시네이션이 생긴다.
- 긴 답변에서 규칙을 잊거나 형식이 무너진다.
- 프롬프트만으로 원하는 캐릭터나 응답 방식을 계속 유지하기 어렵다.
- 좋은 답변과 실패 답변을 따로 관리하지 않으면 개선 방향을 추적하기 어렵다.

이 문제 때문에 이 프로젝트는 "AI가 정답을 만들어주는 앱"이 아니라 "목적별 LoRA에 사용할 학습 데이터 후보를 만들고 검수하는 앱"으로 방향을 잡았다.

LoRA 1차 실험에서 50개 JSONL을 사용해 `Qwen2.5 0.5B` adapter 생성까지 확인했다. 이 결과를 바탕으로 다음 단계는 하나의 말투 데이터셋을 넘어서, 템플릿 기반으로 여러 목적의 LoRA 데이터셋을 만드는 구조로 확장한다.

## 현재 구조

현재 앱은 다음 역할로 나뉜다.

- AI 프로필: 이름, 역할, 말투, 성격, 금지사항, 답변 스타일을 관리한다.
- 기억: 사용자가 추가한 정보를 저장하고 질문과 관련 있는 기억을 프롬프트에 포함한다.
- 채팅: 프로필과 기억을 바탕으로 AI 답변을 받아 실험한다.
- 데이터 제작: 질문, 핵심 사실, 원하는 말투를 입력하고 AI가 초안을 만든다.
- 데이터 관리: 좋은 답변, 수정된 답변, 실패 기록을 저장하고 JSONL로 내보낸다.

앞으로 추가할 구조는 다음과 같다.

- LoRA 프로젝트: 만들고 싶은 LoRA의 목적, 베이스 모델, 템플릿, 체크리스트를 관리한다.
- 템플릿 기반 생성: 사용자가 정한 형식에 맞춰 원하는 개수만큼 데이터 후보를 만든다.
- 자동 검사: JSON 구조, 문장 수, 금지어, 출력 형식 같은 확실한 규칙을 코드로 검사한다.
- AI 평가: 체크리스트 기준으로 후보의 문제점을 찾고 수정 여부를 판단한다.
- 학습 결과 기록: 원본 모델과 LoRA adapter를 붙인 모델의 답변 차이를 기록한다.

## 데이터 흐름

현재 목표로 하는 데이터 제작 흐름은 다음과 같다.

```txt
질문 입력
→ 핵심 사실 입력
→ 원하는 말투와 형식 입력
→ AI 초안 생성
→ 사람이 답변 수정
→ 학습 데이터 후보로 저장
→ 검수 완료 표시
→ 검수 완료 데이터만 JSONL export
→ 파인튜닝 또는 LoRA 학습 실험
```

이 흐름에서 중요한 점은 최종 데이터의 책임을 AI가 아니라 사람이 가진다는 것이다. AI는 초안을 빠르게 만드는 보조 도구이고, 실제 학습에 들어갈 답변은 사람이 수정하고 검수한 결과물이어야 한다.

새로 목표로 하는 템플릿 기반 흐름은 다음과 같다.

```txt
LoRA 프로젝트 생성
→ 템플릿 작성
→ 생성 개수 설정
→ 생성 AI가 후보 작성
→ 수정 AI가 템플릿에 맞게 다듬음
→ 코드 검사와 AI 평가
→ 통과한 후보 저장
→ 사람이 reviewed 처리
→ 프로젝트별 JSONL export
→ LoRA 학습과 비교 기록
```

## 파인튜닝으로 기대하는 것

파인튜닝으로 기대하는 효과는 다음과 같다.

- 원하는 말투를 더 안정적으로 유지한다.
- 답변 길이와 형식을 더 잘 지킨다.
- 특정 상황에서의 반응 방식을 반복 학습한다.
- 매번 긴 시스템 프롬프트를 넣지 않아도 비슷한 스타일을 유지한다.
- 좋은 예시를 통해 "어떤 답변이 좋은 답변인지" 모델에게 보여준다.

다만 파인튜닝은 지식 저장소가 아니다. 최신 정보, 개인 문서, 자주 바뀌는 사실은 파인튜닝보다 검색, 기억, RAG 구조로 다루는 편이 더 적합하다.

## 현재 한계

현재 프로젝트에는 다음 한계가 있다.

- 저장된 좋은 예시 수정과 삭제는 가능하지만, 검수 완료 상태 관리는 아직 없다.
- JSONL export가 검수 완료 데이터만 내보내는 구조가 아니다.
- 직접 검수한 50개 데이터셋은 만들었지만, 안정적인 말투 학습을 기대하려면 100개 이상으로 확장하는 것이 좋다.
- LoRA 1차 학습은 adapter 생성까지 확인했지만, 앱 안에서 학습을 실행하거나 결과를 관리하지는 않는다.
- 50개 좋은 예시를 프롬프트에 참고시키는 방식은 모델 자체를 바꾸지 못한다.
- 작은 로컬 모델은 여전히 중국어 섞임, 냥체 누락, 예시 오염 문제가 생길 수 있다.
- 기억 기능은 단순 검색 기반이라 데이터가 많아지면 정확도와 속도 문제가 생길 수 있다.
- RAG나 벡터 검색 같은 지식 검색 구조는 아직 없다.

## 다음 개선 방향

우선순위는 다음과 같다.

1. 현재 50개 JSONL을 기준으로 작은 LoRA 실험을 준비한다.
2. RTX 3050 8GB 환경에서는 0.5B 또는 1.5B 모델로 먼저 학습 흐름을 검증한다.
3. 학습 전후 질문 10개를 비교해서 효과와 한계를 기록한다.
4. LoRA 프로젝트와 템플릿 개념을 데이터 모델에 반영한다.
5. 템플릿 기반 데이터 후보 생성 흐름을 만든다.
6. 코드 검사, AI 평가, 사람 검수 상태를 분리한다.
7. 프로젝트별 JSONL export를 만든다.
8. 데이터가 부족하면 목적별 기준으로 100개 이상 확장한다.
9. 지식이 필요한 답변은 기억 검색 또는 RAG 구조로 확장한다.

## 포트폴리오 설명 초안

```txt
로컬 LLM의 말투 유지와 사실 정확도 한계를 실험한 뒤, 모델에게 정답 생성을 맡기기보다 사람이 기준을 통제하고 검수하는 데이터 제작 도구를 구현했습니다. 이후 직접 큐레이션한 50개 JSONL 데이터셋으로 LoRA adapter 생성까지 확인했고, 이를 바탕으로 프롬프트와 템플릿에서 목적별 LoRA 데이터셋을 만드는 워크벤치로 방향을 확장했습니다.
```

## 한 문장 요약

이 프로젝트는 AI가 문장을 한 번 생성하는 것을 넘어서, 목적별 LoRA를 위한 데이터 제작, 검수, export, 학습 비교 흐름을 반복 가능하게 설계하는 데 의미가 있다.
