# 요구사항 명세

## 프로젝트 목표

AI Maker Studio는 목적별 LoRA를 만들기 위한 데이터셋 제작 워크벤치다.

현재 목표는 모델을 바로 완성시키는 것이 아니라, 사용자가 입력한 프롬프트와 템플릿을 기준으로 학습 데이터 후보를 만들고, 검수한 뒤 JSONL로 내보내며, 작은 LoRA 학습 실험까지 연결하는 것이다.

## 주요 사용자 시나리오

### 시나리오 1. AI 프로필을 만든다

사용자는 AI 이름, 역할, 말투, 성격, 금지사항, 답변 스타일을 입력한다. 앱은 이 정보를 바탕으로 시스템 프롬프트를 만든다.

### 시나리오 2. 기억을 추가한다

사용자는 AI가 참고해야 할 정보를 기억으로 추가한다. 앱은 질문과 관련 있는 기억 일부를 찾아 시스템 프롬프트에 포함한다.

### 시나리오 3. AI 답변을 실험한다

사용자는 채팅으로 질문을 보내고, 선택한 제공자(`practice`, `ollama`, `openai`)를 통해 답변을 받는다. 좋은 답변은 데이터셋 후보로 저장하고, 실패한 답변은 실패 이유와 함께 기록한다.

### 시나리오 4. 학습 데이터 후보를 만든다

사용자는 질문, 핵심 사실, 원하는 말투와 형식을 입력한다. AI는 초안을 만들고, 사용자는 최종 답변을 수정한 뒤 학습 데이터 후보로 저장한다.

### 시나리오 5. 데이터셋을 검수하고 내보낸다

사용자는 저장된 데이터셋 후보를 다시 열어 보고 수정, 삭제, 검수 완료 처리한다. 검수 완료된 데이터만 JSONL로 export한다.

### 시나리오 6. LoRA 프로젝트를 만든다

사용자는 번역, 말투, 평가, 템플릿 수정 같은 목적을 가진 LoRA 프로젝트를 만든다. 프로젝트에는 이름, 목적, 베이스 모델 후보, 데이터 생성 개수, 템플릿, 체크리스트를 저장한다.

### 시나리오 7. 템플릿으로 데이터 후보를 자동 생성한다

사용자는 템플릿과 생성 개수를 정한다. 앱은 생성 AI, 수정 AI, 평가 AI, 코드 검사기를 거쳐 학습 데이터 후보를 만든다. 통과하지 못한 후보는 수정 단계로 되돌리거나 실패 기록으로 남긴다.

### 시나리오 8. LoRA 학습 결과를 비교한다

사용자는 프로젝트별 JSONL로 짧은 LoRA 학습을 실행하고, 원본 모델과 LoRA adapter를 붙인 모델의 답변 차이를 기록한다.

## 기능 요구사항

### 완료된 요구사항

- AI 프로필 생성과 수정
- 기억 추가와 삭제
- 관련 기억을 시스템 프롬프트에 포함
- `practice`, `ollama`, `openai` 제공자 선택
- AI 답변 저장
- AI 답변 수정 후 저장
- 실패 이유 기록
- 데이터 제작 탭에서 질문, 핵심 사실, 말투 조건 입력
- AI 초안 생성
- 최종 답변을 학습 데이터 후보로 저장
- 전체 데이터셋 JSONL export
- 데이터 비우기
- 앱 전체 초기화

### 아직 필요한 요구사항

- LoRA 프로젝트 생성과 수정
- 템플릿 생성과 수정
- 생성할 데이터 개수 설정
- 템플릿 기반 데이터 후보 자동 생성
- 코드 기반 데이터 검사
- AI 평가 결과 저장
- 데이터 후보 상태 관리: `draft`, `auto_checked`, `reviewed`, `rejected`
- 저장된 데이터셋 후보 다시 열기
- 저장된 데이터셋 후보 수정
- 저장된 데이터셋 후보 삭제
- 검수 완료 표시
- 검수 완료된 데이터만 JSONL export
- 프로젝트별 JSONL export
- 데이터 개수, 검수 개수, 실패 개수 요약
- LoRA 학습 전후 비교 결과 기록

## 비기능 요구사항

- 로컬에서 쉽게 실행할 수 있어야 한다.
- OpenAI API 키가 없어도 `practice` 또는 `ollama`로 흐름을 테스트할 수 있어야 한다.
- 학습 데이터 후보는 사람이 최종 검수할 수 있어야 한다.
- 저장 데이터는 프로젝트 폴더의 `data/app-state.json` 파일에 유지한다.
- JSONL export 형식은 파인튜닝에 재사용하기 쉬운 `messages` 구조를 따른다.
- 데이터가 늘어나도 UI에서 확인, 수정, 삭제하기 쉬워야 한다.
- 템플릿과 체크리스트는 다른 LoRA 프로젝트에도 재사용할 수 있어야 한다.
- 자동 생성된 데이터는 바로 학습에 넣지 않고 검수 상태를 남겨야 한다.

## 범위 밖

- 현재 단계에서는 LoRA 학습 실행을 앱 안에서 자동화하지 않는다.
- 현재 단계에서는 벡터 DB나 RAG를 구현하지 않는다.
- 현재 단계에서는 로그인, 서버 DB, 사용자 계정 관리를 포함하지 않는다.
