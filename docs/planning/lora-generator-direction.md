# LoRA 생성기 방향 기획

## 방향 전환 이유

기존 앱은 AI 프로필과 기억을 바탕으로 답변을 만들고, 좋은 답변을 JSONL 데이터셋으로 저장하는 흐름에 가까웠다.

LoRA 1차 실험을 통해 `Qwen2.5 0.5B`에 50개 JSONL을 학습시켜 adapter가 생성되는 것을 확인했다. 이 결과로 프로젝트의 중심은 단순 채팅이나 좋은 답변 저장이 아니라, 목적별 LoRA를 만들기 위한 데이터 제작과 검수 흐름으로 바뀐다.

새 목표는 다음과 같다.

```txt
프롬프트와 템플릿을 입력하면,
AI가 LoRA 학습에 사용할 데이터 후보를 만들고,
검수와 평가를 거쳐 JSONL로 내보내며,
필요하면 LoRA 학습 실험까지 연결하는 도구를 만든다.
```

## 새 프로젝트 정의

AI Maker Studio는 목적별 LoRA를 만들기 위한 로컬 데이터셋 제작 워크벤치다.

사용자는 번역, 말투, 데이터 평가, 템플릿 수정 같은 목적을 가진 LoRA 프로젝트를 만들고, 각 프로젝트에 맞는 템플릿과 체크리스트를 정의한다. 앱은 그 기준에 따라 학습 데이터 후보를 반복 생성하고, 검수된 데이터만 JSONL로 내보낸다.

## 핵심 개념

### LoRA Project

하나의 LoRA 목적을 나타낸다.

예시:

- `nabi-tone-lora`: 자연스러운 냥체와 짧은 답변 습관 학습
- `translation-lora`: 특정 규칙을 따르는 번역 습관 학습
- `dataset-review-lora`: 학습 데이터 후보를 체크리스트로 평가하는 습관 학습
- `template-fixer-lora`: 초안을 정해진 템플릿에 맞게 다듬는 습관 학습

### Template

AI가 데이터 후보를 만들 때 따라야 하는 입력과 출력 형식이다.

템플릿은 다음 정보를 가진다.

- 목적
- 베이스 모델 후보
- 생성할 데이터 개수
- system prompt
- user 입력 형식
- assistant 출력 형식
- 금지사항
- 체크리스트
- 예시 데이터

### Dataset Candidate

템플릿에 따라 생성된 학습 데이터 후보다.

후보는 바로 학습 데이터가 아니다. 자동 검사와 사람 검수를 거쳐야 한다.

예상 상태:

- `draft`: 생성됨
- `auto_checked`: 코드 검사와 AI 평가를 통과함
- `reviewed`: 사람이 검수 완료함
- `rejected`: 학습 데이터로 쓰지 않음

## 추천 데이터 흐름

```txt
LoRA 프로젝트 생성
→ 템플릿 작성
→ 생성 개수 설정
→ 생성 AI가 데이터 후보 작성
→ 수정 AI가 템플릿에 맞게 다듬음
→ 코드 검사기가 형식, 금지어, 문장 수, JSON 구조 검사
→ 평가 AI가 체크리스트 기준으로 평가
→ 실패하면 수정 AI로 재시도
→ 통과하면 dataset 후보로 저장
→ 사람이 reviewed 처리
→ 프로젝트별 JSONL export
→ LoRA 학습 실험
→ 학습 전후 비교 기록
```

## AI 역할 분리

처음부터 여러 모델을 반드시 쓸 필요는 없다. MVP에서는 같은 제공자와 모델을 역할별 프롬프트로 나누어 사용한다.

나중에 성능이 부족하면 역할별 모델을 분리한다.

- 생성 AI: 템플릿을 보고 데이터 후보를 만든다.
- 수정 AI: 초안을 출력 형식과 말투 기준에 맞게 다듬는다.
- 평가 AI: 체크리스트 기준으로 문제 후보를 찾고 점수를 남긴다.
- 코드 검사기: AI가 아니라 코드로 확실한 규칙을 검사한다.
- 사람 검수자: 최종 학습 데이터 포함 여부를 결정한다.

## 코드 검사기가 맡아야 할 것

AI 평가에 맡기면 흔들리는 부분은 코드로 검사한다.

- JSONL 구조
- `system`, `user`, `assistant` 역할 순서
- 빈 content
- 문장 수
- 금지어
- 존댓말 표현
- 중국어 한자 섞임
- 출력 템플릿 필수 항목

## AI 평가가 맡을 수 있는 것

AI 평가는 최종 판정자가 아니라 보조 평가자로 둔다.

- 질문 의도에 답했는지
- 핵심 사실을 벗어난 내용이 있는지
- 답변이 자연스러운지
- 템플릿 목적에 맞는지
- 수정이 필요한 이유가 무엇인지

## 왜 ChatGPT로 직접 만들지 않고 앱을 만드는가

ChatGPT나 Codex는 데이터 후보를 빠르게 만들 수 있다. 하지만 일회성 대화만으로는 다음을 관리하기 어렵다.

- 어떤 템플릿으로 만들었는지
- 어떤 후보가 탈락했는지
- 탈락 이유가 무엇인지
- 어떤 데이터가 실제 학습에 들어갔는지
- 학습 전후 결과가 어떻게 달라졌는지

이 앱의 의미는 문장을 한 번 생성하는 것이 아니라, 데이터 제작, 검수, 실패 기록, export, LoRA 학습 비교를 반복 가능한 흐름으로 만드는 데 있다.

## MVP 범위

1차 목표는 다음 기능을 문서와 UI 기준으로 고정하는 것이다.

- LoRA 프로젝트 개념 추가
- 템플릿 기반 데이터 생성 기획
- 프로젝트별 데이터셋 관리
- 프로젝트별 JSONL export
- LoRA 학습 전후 비교 기록

실제 구현은 기존 앱을 바로 갈아엎지 않고, 데이터 제작 탭과 데이터 모델부터 점진적으로 바꾼다.

## 장기 확장

- 목적별 LoRA 여러 개 관리
- 생성, 수정, 평가용 LoRA 분리
- 번역 LoRA 프로젝트 추가
- LoRA adapter 병합과 Ollama 등록 흐름 문서화
- 학습 결과를 다시 데이터 생성 파이프라인에 활용
