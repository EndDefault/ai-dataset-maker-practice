# 버전 계획

이 문서는 현재 버전의 기준과 다음 업데이트 범위를 정리한다.

버전은 `v0.x` 단계에서 기능 흐름을 안정화한 뒤, 기본 사용 흐름이 충분히 검증되면 `v1.0.0`으로 올린다.

## 버전 규칙

```txt
v0.1.0
첫 사용 가능 버전

v0.2.0
문서 인덱싱 상태와 문서 처리 신뢰성 개선

v0.2.1
한국어 출력 안정화와 문서 재분석 성능 개선

v0.3.0
실제 embedding/RAG 연결

v0.3.1
RAG 답변 품질과 빈 응답 처리 개선

v1.0.0
로컬 단일 사용자 기준 안정 버전
```

## v0.1.0 기준

`v0.1.0`은 로컬 AI 작업 콘솔의 첫 사용 가능 버전이다.

포함된 기능:

- Streamlit 기반 Home, Documents, Runs, Settings 페이지
- txt, md, 텍스트 기반 pdf 업로드
- 업로드 문서 목록 표시
- 업로드 문서 삭제
- Home에서 사용할 입력 파일을 하나씩 추가하고 제거하는 방식
- 문서 요약
- 문서 검색
- 에러 메시지 분석
- RAG 질의응답 후보 작업
- 실행 기록 SQLite 저장
- Markdown 결과 파일 저장
- 실패 시 Markdown 오류 요약과 `error.json` 저장
- 결과 화면에서 내부 메타데이터 숨김
- Gitmoji 기반 커밋 규칙 정리

제한:

- PDF는 텍스트가 포함된 PDF만 처리한다.
- 스캔 이미지 PDF는 아직 OCR을 하지 않는다.
- PPT/PPTX는 아직 지원하지 않는다.
- `bge-m3` embedding과 `sqlite-vec` 실제 벡터 검색은 아직 연결 전이다.
- `qwen3:4b` 기반 입출력 정제 AI는 아직 실제 모델 호출 전이다.

## v0.2.0 구현 기준

`v0.2.0`은 기능을 크게 늘리기보다, 업로드한 문서가 실제로 검색과 요약에 쓸 수 있는 상태인지 분명히 보여주는 버전이다.

포함된 기능:

- 문서별 인덱싱 상태 표시
- PDF 텍스트 추출 가능 여부 표시
- 스캔 PDF 추정 표시
- 문서별 추출 글자 수 표시
- 문서별 청크 수 표시
- 문서 처리 오류 메시지 정리
- 사용자가 이번 작업에서 참고할 문서와, 앱이 검색 가능하게 준비해 둔 문서를 UI에서 구분

문서 상태 예시:

```txt
업로드됨
인덱싱 완료
텍스트 없음
스캔 PDF 추정
지원하지 않는 파일
오류
```

Documents 페이지에서 보여줄 정보:

- 파일명
- 파일 형식
- 파일 크기
- 문서 상태
- PDF 페이지 수
- 추출 글자 수
- 청크 수
- 마지막 분석 시각
- 삭제 버튼

Home 페이지에서 유지할 개념:

- Add 버튼으로 이번 작업에 참고할 문서를 선택한다.
- 선택된 문서는 이번 실행의 입력 범위다.
- 인덱싱 상태가 좋지 않은 문서는 실행 전에 경고한다.

## v0.2.1 구현 기준

`v0.2.1`은 `v0.2.0`에서 발견한 사용성 문제를 고치는 개선 버전이다.

포함된 기능:

- 생성형 답변 기본 system prompt를 한국어 작업 비서로 고정
- 요약, RAG 질의응답, 에러 분석에서 한국어 출력 안정화
- 영어 응답으로 보이는 결과는 한국어 Markdown으로 한 번 재작성
- 파일 크기와 수정 시간이 바뀌지 않은 문서는 재분석하지 않음
- Documents/Home 렌더링 시 PDF 재분석 비용 감소

## v0.3.0 구현 기준

`v0.3.0`은 OCR보다 실제 embedding/RAG 연결을 먼저 구현하는 버전이다.

포함된 기능:

- `bge-m3` embedding 생성
- 기본 embedding 차원 1024 설정
- `sqlite-vec` `chunk_embeddings` 가상 테이블 생성
- 문서 chunk embedding을 SQLite에 저장
- RAG 질의응답에서 벡터 검색 우선 사용
- 벡터 검색 실패 시 lexical fallback 검색 사용
- 검색 근거 sources에 `search_mode` 기록
- Documents 페이지에 저장된 벡터 row 수 표시

제한:

- 스캔 이미지 PDF OCR은 아직 연결하지 않는다.
- `qwen3:4b` 기반 입출력 정제 AI는 아직 실제 모델 호출 전이다.
- 벡터 검색 품질은 실제 사용 중 검색어와 chunk 크기를 관찰하며 조정한다.

## v0.3.1 개선 기준

`v0.3.1`은 `v0.3.0`에서 실제 연결된 RAG의 답변 품질과 실패 처리를 개선하는 버전이다.

포함된 개선:

- RAG 답변에서 사용자 요청 주제와 무관한 항목 제외
- 표 요청이 있을 때 Markdown 표 형식 강제
- 벡터 검색 결과에 키워드 포함 여부를 반영해 관련 chunk 우선순위 개선
- LLM 응답이 빈 문자열이면 성공 처리하지 않고 재시도 또는 실패 처리
- sources에 근거 파일명과 chunk 정보를 더 명확히 표시
- 예산안처럼 항목/지원 내용/금액을 뽑는 질의의 출력 형식 안정화

남은 관찰:

- 실제 사용 중 금액과 chunk 번호 정확도를 추가 확인한다.
- 숫자 추출이 중요한 질의에는 별도 후처리 검증이 필요할 수 있다.

## UI 개편 시점

큰 UI/UX 개편은 `v0.4.0` 전후가 적당하다.

이유:

- `v0.2.0`에서는 문서 상태, 인덱싱, 스캔 PDF 감지처럼 화면에 보여야 할 정보가 늘어난다.
- `v0.3.0`에서는 OCR 또는 실제 RAG 연결처럼 작업 흐름 자체가 달라질 수 있다.
- 이 흐름이 정리되기 전에 UI를 크게 바꾸면, 다시 갈아엎을 가능성이 높다.

권장 순서:

```txt
v0.2.0
문서 상태와 인덱싱 표시를 먼저 구현한다.

v0.3.0
실제 embedding/RAG 연결을 구현한다.

v0.3.1
RAG 답변 품질과 빈 응답 처리를 개선한다.

v0.4.0
기능 흐름이 보이면 UI/UX를 한 번 크게 정리한다.

v1.0.0
안정화, 문서 정리, 오류 처리, 설정 흐름을 마감한다.
```

`v0.2.0`과 `v0.3.0`에서는 UI를 완전히 갈아엎기보다, 필요한 화면 요소만 작게 추가한다.

`v0.4.0`에서 할 UI 개편 후보:

- Home 작업 실행 흐름 재정리
- Documents 문서 상태 테이블 개선
- Runs 결과 보기 화면 개선
- Settings 모델/DB 상태 표시 개선
- 검색 결과와 참고 문서 표시 방식 개선
- 전체 레이아웃과 색상, 버튼, 경고 상태 정리
