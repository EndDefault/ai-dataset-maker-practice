# 구현 이력

구현 과정에서 바뀐 파일, 설계 결정, 트레이드오프를 기록한다.

## 2026-06-01 데이터 제작 도구 1차 구현

변경 요약:

- AI 프로필 기반 시스템 프롬프트 생성
- 기억 기능 추가
- Ollama, OpenAI, practice 제공자 연결
- AI 답변 저장과 수정 저장 기능 추가
- 실패 기록 기능 추가
- 데이터 제작 탭 추가
- JSONL export 기능 추가

설계 결정:

- 작은 로컬 모델이 사실 정확도와 말투 유지에 약하므로, AI가 정답을 완성하는 구조보다 사람이 핵심 사실을 제공하고 AI가 초안을 만드는 구조로 방향을 잡았다.
- 학습 데이터는 파인튜닝에 쓰기 쉬운 `messages` 배열 형태로 저장한다.
- 서버 DB 없이 브라우저 `localStorage`를 사용해 MVP를 빠르게 검증한다.

트레이드오프:

- `localStorage`는 구현이 단순하지만 여러 기기 동기화나 대량 데이터 관리에는 약하다.
- 단순 기억 검색은 구현이 빠르지만 데이터가 많아지면 정확도와 속도 한계가 생길 수 있다.
- JSONL export는 바로 쓸 수 있는 장점이 있지만, 검수 상태가 없으면 품질 관리가 어렵다.

## 2026-06-02 좋은 예시 선택 기준 개선

변경 요약:

설계 결정:

- 아직 벡터 검색이나 관련도 검색은 적용하지 않고, 현재 데이터 품질을 유지하는 간단한 점수 방식을 먼저 사용한다.

## 2026-06-02 제작 데이터 system 말투 충돌 수정

변경 요약:

- 제작 탭 system prompt에 `원하는 말투/형식`을 직접 포함
- 제작 탭 말투와 형식이 프로필 기본 말투보다 우선한다는 지시 추가

- 학습 데이터에서 system과 user의 말투 지시가 충돌하지 않도록 한다.

## 2026-06-02 냥체 프롬프트 오염 방지

변경 요약:

- AI 요청에 포함하는 최근 대화에서 assistant 답변을 제외
- 실패한 assistant 답변의 어색한 `한다냥` 패턴이 다음 답변에 재학습되지 않도록 수정
- 시스템 프롬프트에 자연스러운 냥체 규칙과 나쁜 끝맺음 예시 추가
- 말투 선택에 `자연스러운 냥체` 옵션 추가

설계 결정:

- 현재 단계에서는 실패 답변이 많으므로 assistant 대화 기록보다 좋은 예시 dataset을 더 신뢰한다.
- 대화 맥락보다 말투 안정화가 우선이라 최근 사용자 질문만 AI 요청에 포함한다.

## 2026-06-02 저장 데이터 수정/삭제 추가

변경 요약:

- 좋은 예시 목록의 각 데이터에 `수정`, `삭제` 버튼 추가
- 수정 시 assistant 답변 내용을 바로 고치고 `updatedAt`을 기록
- 삭제 시 확인 후 dataset에서 제거

설계 결정:

- 잘못 저장한 좋은 답변을 빠르게 바로잡는 것이 목적이므로, 우선 답변 본문 수정에 집중한다.
- 삭제는 dataset 배열에서 제거하므로 이후 JSONL export 대상에서도 제외된다.

## 2026-06-02 좋은 예시 오염 방지 프롬프트 조정

변경 요약:

- 현재 단계에서는 예시 양보다 질문 의도 유지와 짧은 답변 안정성을 우선한다.
