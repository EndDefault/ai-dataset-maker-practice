# 현재 상태

## 한 문장 요약

로컬 LLM, SQLite, embedding, 벡터 검색을 연결해 RAG 문서 질의응답을 연습할 수 있는 Streamlit 앱을 만들었고, 1차 구현은 여기서 종료한다.

## 1차 종료 기준

이 프로젝트는 현재 완성형 제품이 아니라 **AI 협업 개발과 RAG 구조 이해를 위한 연습 프로젝트**로 정리한다.

현재 기준에서 목표는 다음 정도다.

- 문서를 업로드할 수 있다.
- 문서를 텍스트로 추출하고 chunk로 나눌 수 있다.
- chunk와 embedding을 SQLite에 저장할 수 있다.
- 질문을 embedding으로 바꿔 관련 chunk를 검색할 수 있다.
- 검색된 근거를 사용해 로컬 LLM으로 답변을 만들 수 있다.
- 결과를 Markdown으로 저장할 수 있다.
- 평가 스크립트로 기본 동작을 반복 점검할 수 있다.

이 기준은 충족했으므로 1차 구현은 종료 상태로 둔다.

## Ollama 사용 상태

현재 설정값:

| 역할 | 모델 |
| --- | --- |
| 최종 답변 생성 | `qwen3:14b` |
| 입력 정제 후보 | `qwen3:4b` |
| 임베딩 | `bge-m3` |

주의할 점:

- `qwen3:14b`는 RAG 답변 생성에 사용한다.
- `bge-m3`는 문서 chunk와 질문 embedding에 사용한다.
- `qwen3:4b`는 설정에는 있지만, 현재 핵심 흐름에서는 아직 실제 입력 정제 AI로 연결하지 않았다.

## RAG 평가 상태

평가 폴더:

```txt
evals/rag/
```

실행 명령:

```cmd
.venv\Scripts\python.exe evals\rag\run_eval.py --dry-run
.venv\Scripts\python.exe evals\rag\run_eval.py
```

최근 기본 평가 결과:

```txt
5/5 passed
```

다만 이 결과는 “RAG가 완성됐다”는 의미가 아니다.

현재 평가는 다음을 확인하는 기준선이다.

- 실행이 실패하지 않는지
- 답변 Markdown이 생성되는지
- 출처 chunk가 붙는지
- 간단한 기대 단어가 포함되는지
- 모르는 정보에 대해 과하게 지어내지 않는지

답변 품질, 근거 적절성, 숫자 정확도는 아직 사람이 확인해야 한다.

## UI 상태

현재 UI는 1차 구현용 Streamlit 콘솔이다.

이번 단계에서는 UI를 완전히 새로 설계하지 않는다. 이전 UI 실험에서 불필요한 내부 상태 카드와 설정 정보가 화면에 과하게 노출되는 문제가 있었기 때문에, 현재는 필요한 화면만 남겨둔다.

다음에 UI를 다시 만들 경우 먼저 정해야 할 것:

- 버튼 크기
- 글자 크기
- 색상 규칙
- 여백 규칙
- 페이지별 정보 우선순위
- 필요한 정보와 숨겨야 할 내부 정보
- 라이트/다크 모드 기준

## 이번 단계에서 배운 점

- AI에게 “예쁘게 만들어줘”라고만 하면 불필요한 UI와 더미 정보가 들어갈 수 있다.
- RAG 품질은 모델보다 문서 파싱과 chunk 품질에 크게 영향을 받는다.
- 자동 평가는 성능 보장이 아니라 문제를 찾는 장치다.
- 학습용 프로젝트에서는 완성도보다 구조를 이해하고 한계를 기록하는 것이 중요하다.
- AI를 잘 쓰려면 요구사항뿐 아니라 제거할 것, 유지할 것, 판단 기준을 명확히 말해야 한다.
