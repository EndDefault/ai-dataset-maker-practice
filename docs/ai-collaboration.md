# AI 협업 개발 기록

## 목적

이 문서는 이 프로젝트에서 AI를 어떻게 활용했는지 기록하기 위한 문서다.

이 프로젝트는 RAG 앱을 완성품으로 만드는 것보다, AI와 함께 요구사항을 정리하고, 구현하고, 결과를 검토하고, 한계를 문서화하는 과정을 연습하는 데 의미가 있다.

## AI를 사용한 방식

AI는 다음 작업에 사용했다.

- 프로젝트 방향 정리
- 기능 후보 분해
- Streamlit UI 초안 작성
- RAG 구조 설계 보조
- Ollama 호출 구조 정리
- SQLite / sqlite-vec 저장 흐름 구현 보조
- 문서 chunk와 embedding 흐름 점검
- UI 결과 검토와 불필요한 요소 제거
- RAG 평가 스크립트 작성
- 평가 결과 요약
- README와 docs 정리

## 사람이 판단한 부분

AI가 만든 결과를 그대로 받아들이지 않고, 다음 부분은 직접 판단했다.

- 프로젝트를 완성형 서비스가 아니라 연습용 프로젝트로 정리하기
- 성능보다 구조 이해와 테스트 가능성을 우선하기
- 불필요한 내부 상태 카드 제거하기
- Settings, Documents, Home에 중복 노출되던 모델/DB 정보를 줄이기
- UI를 지금 당장 완전히 새로 만들지 않기
- `train`이 아니라 RAG 평가용 폴더를 만들기
- 평가 결과를 성능 보장이 아니라 기본 동작 점검으로 보기

## 이번 프로젝트에서 배운 점

### AI에게 막연히 맡기면 결과가 흔들린다

“UI를 고쳐줘”처럼 넓게 요청하면 AI가 필요 없는 카드, 설정값, 내부 상태 정보를 화면에 넣을 수 있다.

앞으로 UI를 만들 때는 먼저 아래 기준을 정해야 한다.

- 어떤 정보가 사용자에게 필요한지
- 어떤 정보는 내부 정보라 숨겨야 하는지
- 버튼 크기와 글자 크기
- 색상 규칙
- 페이지별 정보 우선순위
- 라이트/다크 모드 기준

### RAG는 모델만의 문제가 아니다

답변 품질이 낮을 때 바로 모델 성능만 의심하면 안 된다.

먼저 봐야 할 것은 다음이다.

- PDF에서 텍스트가 제대로 추출됐는지
- 문서가 적절한 chunk로 나뉘었는지
- 검색된 chunk가 질문과 실제로 관련 있는지
- 모델 프롬프트에 충분한 근거가 들어갔는지
- 답변이 근거를 벗어나지 않았는지

### 자동 평가는 기준선이다

현재 `evals/rag/`의 평가는 기본 동작 점검용이다.

통과했다는 것은 다음 정도를 의미한다.

- 앱이 질문을 실행할 수 있다.
- RAG 결과가 생성된다.
- 출처 chunk가 붙는다.
- 최소한의 기대 단어가 포함된다.

하지만 이것만으로 답변 품질이 좋다고 말할 수는 없다.

## Codex, Skill, MCP에 대한 현재 판단

OpenAI Codex 문서에는 `AGENTS.md`, Skills, MCP 같은 확장 방법이 있다.

현재 판단:

- 지금 당장 Skill이나 MCP를 도입할 필요는 없다.
- 반복 작업이 명확해지면 Skill을 만들 수 있다.
- 외부 도구나 서비스 연결이 필요해지면 MCP를 검토한다.
- 지금은 프로젝트 문서를 정리하고, 평가 기준을 만드는 것이 더 중요하다.

나중에 Skill 후보:

| 후보 Skill | 역할 |
| --- | --- |
| `rag-eval` | RAG 평가 실행, 결과 요약, 실패 케이스 정리 |
| `docs-update` | 구현 후 README/docs/checklist 갱신 |
| `streamlit-ui-review` | UI 수정 전 규칙 확인과 불필요한 내부 정보 점검 |

## 이 프로젝트를 설명하는 방식

이 프로젝트는 다음처럼 설명하는 것이 가장 정확하다.

```txt
로컬 LLM과 RAG 구조를 연습하기 위해 만든 AI 협업 개발 프로젝트다.
AI를 코드 생성기로만 사용한 것이 아니라, 요구사항 정리, 구조 설계,
구현 보조, 결과 검토, 평가 자동화, 문서화까지 함께 실험했다.
```

피해야 할 설명:

```txt
고성능 RAG 서비스를 완성했다.
문서를 완벽히 이해하는 AI를 만들었다.
모델을 학습시켰다.
```

현재 프로젝트는 이런 표현보다 “로컬 RAG 앱의 기본 구조를 만들고 테스트할 수 있게 했다”는 표현이 맞다.

## 다음에 더 잘하기 위한 규칙

AI에게 요청하기 전에 다음을 먼저 정한다.

1. 목표
2. 필요한 기능
3. 필요 없는 기능
4. 화면에 보여줄 정보
5. 숨길 내부 정보
6. 성공 기준
7. 테스트 방법

이 기준을 먼저 정하면 AI가 만든 결과를 더 쉽게 검토할 수 있다.
